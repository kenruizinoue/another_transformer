# another_transformer Project Plan

## Goal

An open-source iOS app that transforms audio into text. The user records audio
(and recording keeps running while the iPhone is locked), saves and lists
recordings, plays them back, transcribes a recording into text using one of three
selectable engines, and then copies the text or exports it to PDF. Text to audio
is a planned future direction, not built in this plan.

## Expected behavior

- Record audio to a saved file; recording survives the phone locking.
- See a list of saved recordings with title, date, and duration.
- Play back, rename, and delete a recording.
- Transcribe a recording to text with a chosen engine and a graceful fallback:
  - `apple` (default): on-device Apple Speech, offline, no key.
  - `whisper`: on-device Whisper via `whisper.rn`, offline, one-time model download.
  - `openai`: cloud, calls OpenAI transcription API directly with the user's own
    key from `.env`. Router preference order with fallback `whisper -> apple -> openai`.
- Copy the transcript to the clipboard or export it as a PDF.

## Stack and layout

Expo SDK 57 + TypeScript + expo-router. Rules live in `standards/base-sdlc.md`
(mandatory) and `standards/react-native.md`. The Expo template uses a `src/`
layout, so the standard's structure maps as:

```text
src/app/            # expo-router screens (thin)
src/components/      # reusable presentational UI
src/hooks/           # stateful workflow logic
src/lib/domain/      # types and gateway interfaces
src/lib/adapters/    # storage, native, and HTTP implementations
src/lib/utils/       # pure helpers + unit tests
.maestro/            # E2E flows (added late, only when approved)
```

Native configuration (background audio mode, microphone and speech permissions)
is declared in `app.json` via config plugins, because `/ios` and `/android` are
gitignored and regenerated by Expo continuous native generation. Features that
touch native modules (audio recording, Whisper, speech recognition) require an
EAS or local dev build, not Expo Go.

## Conventions

- Branch policy for this project: work directly on `master`, no feature branches.
- Never commit unless the user explicitly asks. A ticket ends by running checks
  and updating this file's status, then pausing for review.
- No em dashes anywhere.
- No secret keys in git. `.env` is gitignored; `.env.example` is committed.
- Tickets are numbered T1..Tn for reference by Prompt 3.

## Verification commands

```bash
npm test              # jest-expo + React Native Testing Library
npx tsc --noEmit      # typecheck
npm run lint          # eslint-config-expo
# Manual, native features (background recording, on-device STT): dev build on a
# device or simulator via `npx expo run:ios` or an EAS development build.
npm run e2e           # Maestro; only after E2E is approved and added
```

A phase is not done until its CI is green on `master`.

## Phase 1 - Foundation

App shell, testing, CI, and the domain and storage boundaries everything else
builds on.

### Ticket 1 - Test runner and smoke test

Objective:

- Wire Jest with the `jest-expo` preset and React Native Testing Library, and add
  npm scripts (`test`, `test:watch`, `typecheck`, `lint`).

TDD work:

- A single smoke test that renders the root screen without crashing. No feature
  logic in this ticket.

Edge cases:

- None yet; this only proves the runner works.

Acceptance criteria:

- `npm test` runs and the smoke test passes.
- `npx tsc --noEmit` passes.

### Ticket 2 - Mobile CI workflow

Objective:

- Add a GitHub Actions workflow that runs `npm ci`, `npm test`, `npx tsc --noEmit`,
  and `npm run lint` on push and PR to `master`.

TDD work:

- No product code. The workflow is validated by a green run on `master`.

Edge cases:

- Workflow hygiene per `standards/base-sdlc.md`: `permissions: contents: read`,
  a concurrency group with cancel-in-progress, `timeout-minutes`, and npm cache.

Acceptance criteria:

- CI is green on `master` running test, typecheck, and lint.

### Ticket 3 - App shell and navigation

Objective:

- Replace the template demo screens with the real app shell: a home screen that
  is the Recordings list (empty state for now) and a Settings screen. Respect
  safe areas on every top-level screen.

TDD work:

- Screen render tests: home shows the empty state; navigation to Settings works.

Edge cases:

- Empty recordings list renders a clear empty state, not a blank screen.

Acceptance criteria:

- First screen is the usable app (recordings), not a splash or marketing screen.
- Render tests pass; `tsc` and lint pass.

### Ticket 4 - Domain types and gateway interfaces

Objective:

- Define `Recording` and related types, a `RecordingStore` gateway interface, and
  a `Transcriber` gateway interface in `src/lib/domain/`. Add pure helpers (for
  example a title generator) in `src/lib/utils/`.

TDD work:

- Unit tests for the pure helpers (title formatting, duration formatting).

Edge cases:

- Title generator handles missing or duplicate timestamps deterministically.

Acceptance criteria:

- Interfaces compile and are consumed only as types by later tickets.
- Helper unit tests pass.

### Ticket 5 - Storage adapter

Objective:

- Implement `RecordingStore` in `src/lib/adapters/` using `expo-file-system` for
  audio files and a local JSON index for metadata (id, title, createdAt,
  durationMs, transcript, fileUri).

TDD work:

- Failing tests first: save, list, get, rename, delete, and transcript update,
  with the file system mocked at the adapter boundary.

Edge cases:

- Missing or corrupt index file recovers to an empty list.
- Deleting a recording removes both the file and its index entry.

Acceptance criteria:

- All store operations pass their tests against the mocked file system.

## Phase 2 - Recording

Capture audio to a saved file, including while the phone is locked.

### Ticket 6 - Audio capture to WAV

Objective:

- A recording hook that records 16 kHz mono WAV via the Expo audio API, exposes
  start and stop, and saves the result through `RecordingStore`.

TDD work:

- Hook tests with the native audio module mocked: start produces a file uri,
  stop saves a recording with a duration.

Edge cases:

- Stop called with no active recording is a no-op.
- A zero-length recording is discarded, not saved.

Acceptance criteria:

- Recording hook tests pass; a saved recording appears in the store.

### Ticket 7 - Background and locked recording

Objective:

- Configure `app.json` for `UIBackgroundModes: ["audio"]` and set the audio
  session so recording continues when the app is backgrounded or the phone is
  locked. Document the dev-build requirement.

TDD work:

- Unit-test the audio-session configuration helper (the options object it builds).

Edge cases:

- App returns to foreground mid-recording and the session is still valid.
- Interruption (a phone call) stops and saves what was captured.

Acceptance criteria:

- Configuration helper test passes.
- Manual, on a dev build: start recording, lock the phone, wait, unlock, and the
  recording is still running and saves correctly. Recorded as a manual check,
  not automated here.

### Ticket 8 - Microphone permission and record UI

Objective:

- A record screen with a record and stop control, elapsed time, and permission
  handling. Declare `NSMicrophoneUsageDescription` in `app.json`.

TDD work:

- Screen tests with the hook injected: granted permission shows the recorder;
  denied permission shows a clear denied state with a path to Settings.

Edge cases:

- Permission denied, permission undetermined then granted, and permission
  revoked while on the screen.

Acceptance criteria:

- Record screen tests pass for granted and denied paths.

### Ticket 9 - CI for Phase 2

Objective:

- Ensure the new recording tests run in CI without native modules by adding the
  needed Jest mocks and setup, and keep the pipeline green.

TDD work:

- No new product code; add test mocks and setup only.

Edge cases:

- CI has no native audio module, so mocks must cover it.

Acceptance criteria:

- CI is green on `master` with the Phase 2 tests included.

## Phase 4 - Transcription

Turn a recording into text with three selectable engines and a fallback chain.

### Ticket 14 - Env config and OpenAI adapter

Objective:

- Add `.env.example` with an empty `EXPO_PUBLIC_OPENAI_API_KEY`, an env helper in
  `src/lib` that reads the key with static access and validates presence, and an
  `openai` transcriber adapter that posts audio to the OpenAI transcription API.

TDD work:

- Adapter tests with `fetch` mocked: success returns text; non-200 and network
  error return null; missing key returns null without calling `fetch`.

Edge cases:

- Missing or blank key, API error response, and empty transcript.

Acceptance criteria:

- OpenAI adapter tests pass; no key is ever committed.

### Ticket 15 - Apple Speech adapter

Objective:

- An `apple` transcriber adapter using `expo-speech-recognition` to transcribe a
  recorded file on device, returning `string | null`.

TDD work:

- Adapter tests with the speech module mocked: result resolves text; error,
  timeout, and unavailable resolve null.

Edge cases:

- Not available on non-iOS, permission denied, and empty result.

Acceptance criteria:

- Apple adapter tests pass for the result and all null paths.

### Ticket 16 - Whisper adapter and model download

Objective:

- A `whisper` transcriber adapter using `whisper.rn`, plus model download and
  readiness management (download, progress, ready check, delete).

TDD work:

- Tests for the model-readiness state machine and adapter routing with the native
  context mocked.

Edge cases:

- Model not downloaded, download interrupted, and transcription failure fall back
  to null so the router can move on.

Acceptance criteria:

- Whisper model-state and adapter tests pass; adapter returns null when the model
  is not ready.

### Ticket 17 - Engine router, preference, and Settings toggle

Objective:

- A router that selects an engine from a stored preference (AsyncStorage) with
  fallback `whisper -> apple -> openai`, and a Settings toggle to choose the
  engine.

TDD work:

- Router tests with fake adapters: each preference picks the right engine and
  falls back correctly when an engine returns null.

Edge cases:

- Unset or legacy preference defaults to `apple`; all engines fail returns a
  clear no-transcript result.

Acceptance criteria:

- Router and preference tests pass; the Settings toggle persists the choice.

### Ticket 18 - Transcribe action and transcript display

Objective:

- A transcribe action on a recording that runs the router, saves the transcript
  to the recording, and shows it with loading, empty, and error states.

TDD work:

- Hook and screen tests with an injected fake `Transcriber`: pending, success
  attaches transcript, and failure shows an error.

Edge cases:

- Re-transcribing overwrites the previous transcript; transcribing while offline
  with only the cloud engine selected shows a clear error.

Acceptance criteria:

- Transcribe flow tests pass and the transcript is saved to the recording.

### Ticket 19 - CI for Phase 4

Objective:

- Ensure the transcription tests run in CI with native modules and `fetch`
  mocked, and keep the pipeline green. Confirm no real key is required for CI.

TDD work:

- Test mocks and setup only.

Acceptance criteria:

- CI is green on `master` with the Phase 4 tests included.
